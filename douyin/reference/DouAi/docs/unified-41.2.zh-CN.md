**抖音融合 41.2：六模块功能整合说明**

这是针对用户提供的抖音 41.2.0 APK 制作的本地融合工程，以 DouAi 0.2.66 的公开源码为基础，整合此前六个模块的功能目标，并为失效的内部接口增加新适配或替代实现。它不是上游正式发布包，也没有使用上游发布签名。

适配对象为用户提供的 `com.ss.android.ugc.aweme`、`41.2.0 / 410200`，原 APK SHA-256 为 `4d161a8eb4da14ee9931b87476e9f0de3847797006e3485e51c4cf497a9d5a99`。同版本其他构建仍需校验。模块要求 Android 9+；本次提供现代 API102 和传统 API82 两个独立构建，版本均为 `0.2.68 / 169`，每次只启用其中一个。

| 文件 | 框架入口与选择 |
| --- | --- |
| `Douyin-Unified-41.2-download3-modern.apk` | 支持 libxposed API102 的框架；包名 `io.github.yudigaga.douai.adapt412`，可覆盖原融合包升级 |
| `Douyin-Unified-41.2-download3-legacy.apk` | 支持传统 Xposed API82 的框架；包名 `io.github.yudigaga.douai.legacy.adapt412`，桌面配置属于另一个应用 |

传统兼容包使用真实 API102 接口类型和传统框架桥接，只有 `assets/xposed_init` 入口，不含现代入口；现代包只有现代入口。传统包没有原生 API102 的远程服务、反优化或类初始化 Hook 能力。其原方法调用不能保证与其他增强模块的跨模块组合顺序，应停用其他模块对抖音的作用域。框架名称和版本尚未从用户手机取得，因此本地编译成功不代表特定 LSPatch/LSPosed 版本已实测兼容。

两个桌面应用的配置各自保存；抖音中的融合存储命名空间共用。切换版本时，新的桌面配置尚为空，配置桥会读取已有的抖音融合设置；桌面已有配置时以该版本桌面保存的内容为准。抖音中的融合历史、媒体来源和扫描确认也会保留，因此每次只启用一个版本。

宿主校验首先比对完整原包 SHA-256。仅重签名、ZIP 压缩/顺序/注释发生变化时，会继续比对固定的二进制 Manifest 和全部业务内容摘要；DEX、资源、assets、原生库及 `META-INF/services` 均须一致。改过 Manifest 或实际运行代码的补丁包仍会给出拒绝原因；不因同为“41.2.0”就套用规则。此内容校验不等于已经支持任意 LSPatch 重打包。

所有功能在一个 APK、一套设置和一套运行诊断中管理。菜单完整显示不等于每个 Hook 已安装：各能力分别记录成功或失败，匹配不唯一、接口不符和未支持的资源不会被强行套用。

原模块中互相重叠的功能使用统一实现。布局、聊天气泡或动作菜单可以与原版不同；对应操作保留同一目的。替代实现不会凭旧混淆名称随机选择一个相似方法。

**试用方式**

1. 按框架能力安装上表中的一个 APK。不要同时启用两个融合包；传统包也不要与旧融合包同时作用于抖音。
2. 在框架中启用融合模块，作用域选择这份抖音。先停用原六个模块在抖音中的作用域，避免同一功能重复处理。
3. 桌面打开模块应用，点 **“功能设置”**，即可打开完整 14 类设置和搜索，无需先连接框架。这里的参数可以离线保存。
4. 完全退出并重新打开抖音。注入回调到达后，右下角出现 **“融合设置”**；身份校验失败时显示 **“融合诊断”**，可查看并复制具体原因。首次扫描会显示准备、身份核对、DEX 进度及结果，缓存命中会显示缓存状态。
5. 如果能在抖音自身设置中插入原生行，其名称同样是 **“融合设置”**。该行受抖音布局影响；右下角入口和桌面设置可独立使用。右下角的 × 只隐藏本次运行入口，重启抖音后恢复。
6. 按需开启各功能；AI 模型、第三方语音、WebDAV 需要填写自己的服务配置。自动发送类设置不要求每一条再确认，应先核对范围和额度。
7. 返回模块主页查看注入回执及配置同步状态。**“未收到抖音注入回执”** 表示尚无模块进入宿主的证据；**“最近回执”** 标有保存时间，仅为历史记录。扫描完成只代表定位阶段结束，各项 Hook 结果分别显示。

桌面和抖音通过校验真实调用 UID 的配置桥同步，不再依赖框架远程偏好接口。两端同时改不同设置会合并；同时改同一个设置发生冲突时保留模块应用端较新的值，并在同步状态中说明。框架远程服务未连接不等于宿主未注入，应以抖音回执判断。若配置监听受框架限制，重新打开抖音会再次读取配置。

桌面可配置参数、名单 ID 和导入导出配置。抖音联系人读取、下载任务、分析历史、真实对话/发送、音频文件导入、语音试听和目录授权，需要在抖音内操作，以使用抖音实际拥有的数据和文件权限。

旧包存在进度初始化未调用、不支持的远程偏好接口在扫描前抛异常，以及校验失败时连诊断界面也不创建等路径。本次将身份校验移到后台、提前建立诊断，并补上上述两个独立设置入口。框架完全没有执行模块时，宿主内界面仍无从出现；此时桌面回执会明确显示尚未收到。

常用入口：作品长按面板的下载项目，或“分享 → 保存本地”，均进入融合媒体选择。视频子页可选编码来源或“提取视频原声 MP3”；作者头像在媒体分类根页。先在“下载相关”启用下载菜单、选择“官方下载”，关闭“直接保存全部媒体”便于首次查看来源；它不是必须开启的总开关。只有官方下载地址的作品可明确选择 Down（可能带水印）；不会把它悄悄作为无水印播放源。保存结果和失败阶段在“下载相关 → 下载任务”。评论先打开原生长按面板，再长按其中的菜单项进入评论工具。私信长按面板可进入“消息工具”。WebDAV 在“下载相关”，定时、彩虹、消息隐私和关注确认等在“基本功能 → 统一增强”。

下载修复版同时处理长按和分享面板入口、`new_download_addr` 及显式 `download_url_list`、直接保存选项的即时更新。详情见同目录《下载修复说明.md》。长按右下角“融合设置”可复制当前模块版本、两个下载入口的点击次数、来源可用状态及最近阶段；这些状态区分“入口已接管”“任务已提交”和“文件实际已保存”。

融合包使用独立包名、配置、自动化账本/历史、消息状态、分析与侧写目录、聊天记忆、音频来源和扫描/日志命名空间。公开保存目录仍按用户选择，WebDAV 中使用自己的服务器目录。它不会自动导入原模块配置，默认也不会启用旧自动发送配置。

**验证边界**

桌面验证包括新宿主的完整规则扫描、关键 DEX 指令/字段注解、行为单元测试、真实 MP3 编码与解码、实况静态/动态两部分解析、保存/取消/清理/隔离，以及编译和 APK 签名。最后一次构建、测试计数、哈希和文件位置见交付目录的 `manifest.json`。

最终回归计数见同目录 `manifest.json`，包含 243 条新宿主规则的唯一匹配、实际下载点击回调，以及来源选择 → 本地测试 HTTP 响应 → 指定文件夹写入内容的检查；两项历史宿主检查不计为 41.2 成功。构建、两个 APK 的入口隔离/签名和文件哈希同样保留原始日志。Lint 因混淆名称解析器崩溃，显式排除 `BlockedPrivateApi`、`DiscouragedPrivateApi`、`PrivateApi`、`SoonBlockedPrivateApi` 四个检测项目。传统兼容引导函数承担嵌入式框架的绑定职责，因此仅在该私有函数对 `XposedInternalApi` 作带理由的单点标注，现代包不含该代码；没有全局关闭该检查。其余检查结果分别记录，不将排除项写成已通过。

没有连接手机，因此还没有验证具体 LSPosed 实现的回调、真机 MediaCodec、抖音页面最终布局、服务器受理结果和 vivo 相册对实况格式的呈现。配置中有开关、规则唯一或桌面测试通过，都不会被描述为这些结果已经通过。

私信媒体保存针对宿主已经取得的 URL 或可读缓存。只有 vid/密钥而没有可读来源的加密媒体，需要先由宿主加载；本工程没有伪造任意加密内容解码能力。MP3 编码接受单/双声道 PCM16 或 float，空音轨/不支持的格式会失败并清理临时文件。画质、下载及游戏资源选择也只使用宿主实际提供的内容。
