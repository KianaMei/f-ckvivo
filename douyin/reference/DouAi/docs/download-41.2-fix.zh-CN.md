**抖音融合 41.2 下载修复版3：0.2.68 / 169**

用户反馈“下载链接不存在”和“不允许下载”后，原包检查和失败回归定位到了下载流程的实际断路。上一版能显示设置、规则唯一和菜单测试通过，没有证明用户点击能执行模块保存；这个验证缺口在本次补齐。

已修复的路径：

- 长按面板下载：此前默认设置仍放行原生动作；媒体解析为空时也会退回原生报错。41.2 开启模块下载后，直接进入完整的融合媒体选择。缺少来源由模块说明，不再静默调用原生拒绝分支。
- 分享面板保存本地：它使用另一个共用的 `X.0xqk.execute(Context, SharePackage)`，之前完全绕开长按面板 Hook。新版本按原包唯一规则捕获此入口，从已验证的 `b:Aweme` 读取当前作品，和长按下载共用处理。
- 媒体地址：补齐 `Video.new_download_addr`，以及显式下载 URL 模型中的 `download_url_list`。只有这类地址时，会作为 Down 来源明确标注“可能带水印”；不将其冒充为播放源或无水印源。
- 直接保存：`download_official_direct` 现在能即时更新原生与手势入口。没有符合无水印设置的直接保存来源时，转到来源选择，由用户明确选 Down，不自动降低设置。
- 会话生命周期：worker 更新配置立即撤销旧按钮的有效性，再在主线程关闭选择器；下载界面异常不会传回抖音点击调用。没有可显示页面时明确提示。

初次验证操作：

1. 覆盖安装与当前框架对应的 modern 或 legacy 包，每次只启用一个，彻底结束抖音进程后重新打开。模块应显示 `0.2.68 / 169`、抖音 `41.2.0 / 410200`。
2. 在“融合设置 → 下载相关”，开启“启用下载菜单”，选择“官方下载”，先关闭“直接保存全部媒体”，保存位置先用默认或在抖音内授权文件夹。
3. 找一个能正常播放的普通视频，点“分享 → 保存本地”，或作品长按面板里的下载。应出现“保存媒体”分类，进入“视频 → 保存视频”；仅有下载源时进入“选择编码 / 下载来源 → Down”。
4. 到“下载相关 → 下载任务”确认任务是否完成。队列已接收不代表文件已经写入。
5. 若仍失败，长按右下角“融合设置”并点“复制诊断”。新版附有模块版本、长按面板/分享面板点击次数、最近作品是否有播放或官方下载地址、开关值和最近阶段；其中没有媒体 URL、账号密钥或服务凭据。

工程验证包括实际原包字段/方法指令，新的失败回归和修复后回归。完整保存测试使用本机 MockWebServer 的真实 HTTP 响应、实际 DownloadTransfer 和 SAF 文件提交，断言请求路径及最终文件字节。它们不访问用户账号，也不执行抖音 APK；真机与抖音 CDN 的行为仍需设备验证。最终测试计数、签名和哈希见交付目录 `manifest.json`。

该改动针对下载链路，不据此宣称其他所有功能均已通过真机验证。抖音未下发的媒体、不能读取的加密内容或过期/拒绝的远程地址，不会因为开关开启而变成可用来源。
