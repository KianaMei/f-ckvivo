# kiroot × 6.12.81 移植（2026-11-27）

> 目标：把 kiroot 那套「原位改 cred、零常驻内存」的临时 root 从 6.12.58
> （`gdd6fd5c98918` / tag 7742，本机在跑）搬到 6.12.81
> （`6.12.81-android16-6-gc3e244f20fca-abogki576505657-4k`，PD2545 下一版 OTA）。
> 全程离线：只用已归档的 kernel Image + 已装 kiroot 的 APK，不碰设备分区、不装包。

## 1. 结论

已经做完了，只剩一次实机首测。

| 需要 build 专属的部分 | 状态 |
|---|---|
| 225 条符号→链接期地址表 | **已重建**，225/225 全部命中 |
| `load_module` 内 4 个探针站点偏移 | **已重定位**（A/B 反汇编确认） |
| `struct cred` 字段偏移（`cred+0x40` / `+0x42`） | **不需要改**，两版 BTF 完全一致 |

## 2. 为什么站点是「bl + 4」

`poc_tmp_root`（Rust、9,130,848 B）里没有任何内核符号字面量，唯一 4 处 build 相关常量是：

```text
p:m2 load_module+0x28dc   p:m3 load_module+0x2924
p:m4 load_module+0x2948   p:m5 load_module+0x2964
```

反汇编 6.12.58 的 `load_module`（`0xffffffc080502688..0xffffffc080505780`，span 0x30f8）后，四个地址全部落在 `bl` 的**下一条指令**上，也就是取返回值的分支点：

| 站点（58） | 前置调用 | 站点指令 |
|---|---|---|
| `+0x28dc` | `blocking_notifier_call_chain_robust` | `and w8, w0, #0xffff7fff` |
| `+0x2924` | `parse_args` | `mov x26, x0` |
| `+0x2948` | `mod_sysfs_setup` | `tbnz w0, #0x1f, …` |
| `+0x2964` | `codetag_load_module` | `nop` |

6.12.81 的 `load_module`（`0xffffffc08057c4e4..0xffffffc08057f62c`，span 0x3148）里，同样四个调用的位置与**指令形状完全一致**，且相邻间隔同为 `0x48 / 0x24 / 0x1c / 0xc`，据此得到新站点：

| 旧（6.12.58） | 新（6.12.81） | 前置调用 |
|---|---|---|
| `load_module+0x28dc` | `load_module+0x2db0` | `blocking_notifier_call_chain_robust` |
| `load_module+0x2924` | `load_module+0x2df8` | `parse_args` |
| `load_module+0x2948` | `load_module+0x2e1c` | `mod_sysfs_setup` |
| `load_module+0x2964` | `load_module+0x2e38` | `codetag_load_module` |

## 3. 提取链的可信度

符号表不是猜出来的，是拿**真值锚点**校出来的：

- 6.12.58：用 kiroot 自带的 225 条表做锚点反解 offsets 数组起点，结果 **225/225 精确命中**，
  说明 `kallsyms_names`（128,943 条）与 `kallsyms_offsets` 的对齐正确；
- 6.12.81：同一套 names/markers 解码，`offsets` 数组末尾与 `kallsyms_relative_base`
  （`0xffffffc080000000`）**gap=0** 严丝合缝，`offsets[0]=0`、全表单调，133,660 条符号；
- 两版基址同为 `0xffffffc080000000`，与 `ksu_patch.txt` 的地址域、语义一致（链接期地址，
  KASLR slide 由 exploit 上机自算）。

## 5. 复现

```bash
# 1) 重建 payload + 表（输入为 6.12.81 的 Image 或其 ELF 包装）
python originos/root/kiroot-61281/tools/build_61281.py \
  --image cache/new.o --outdir cache/scratch/kiroot_retarget

# 2) 换进 APK 并重签
python originos/root/kiroot-61281/tools/repack_apk.py
"$SDK/build-tools/36.1.0/zipalign.exe" -f -p 4 kiroot-81-unsigned.apk kiroot-81-aligned.apk
"$SDK/build-tools/36.1.0/apksigner.bat" sign --ks shared/signing/debug.keystore \
  --ks-pass pass:android --key-pass pass:android --ks-key-alias androiddebugkey \
  --out kiroot-81.apk kiroot-81-aligned.apk
```

工具：`tools/kallsyms2.py`（markers 锚定解码 + 锚点/结构双模式定 offsets）、
`tools/kdis.py`（布置 ELF 包装的 `.data` 映射与 capstone 反汇编）、
`tools/btf.py`（结构体布局）、`tools/repack_apk.py`。

## 6. 还没验证的一件事

kiroot 只跑过 6.12.58）。离线能配齐的东西都配齐了，剩下的是**一次单发首测**，
而且只能在设备真的升到 6.12.81 之后做。首测失败的后果是 panic / 丢 root，
因此仍按红线执行：不主动 OTA、不写设备临时文件、屏幕解锁且用户在场、单发不重试。
