# kaslana 部署套件（两文件拷到 kaslana 任意目录，如 D:\adb-mcp-kit\）

## 一次性安装（5 分钟）

1. **拷贝两个文件**到 kaslana（微信/网盘/U 盘均可）：
   - `shared/tools/adb-mcp/kaslana/Resolve-AdbMcp.ps1`（部署/同步脚本）
   - `shared/tools/adb-mcp/secrets/token.txt`（Bearer token，随主仓 git 同步）

2. **在 kaslana 上**（普通 PowerShell，不需要管理员）：
   ```powershell
   cd <你放套件的目录>
   powershell -ExecutionPolicy Bypass -File .\Resolve-AdbMcp.ps1 -Token (Get-Content .\token.txt -Raw).Trim() -Install -Schedule
   ```
   这一步会：
   - 查公网 DNS TXT `adb-mcp-tunnel.mamba-out.com` 拿当前隧道 URL（DoH，绕开本地 DNS/代理污染）
   - 写入 `%USERPROFILE%\.gemini\config\mcp_config.json`（合并模式，不动已有条目）
   - 把 token 存到 `%USERPROFILE%\.adb-mcp\token.txt`
   - 注册每 5 分钟自动同步的计划任务（隧道 URL 变了自动改配置）

3. **生效方式（按使用形态二选一）**：
   - **agy CLI / paseo 里的 antigravity agent**：对 agent 执行 **Reload agent**（"Reload agent to update
     skills, MCPs or login status"），配置从 `~/.gemini/config/mcp_config.json` 重读。
   - **Antigravity IDE / 桌面 App 直连**（架构方向：跳过 paseo，见 README「当前进度」）：
     配置入口待定位确认（IDE 内置 MCP 管理页），确认后在此补充。

4. 验证：让 agent 说“调用 adb_devices 列一下设备”。
   预期返回 `10AG632QLS002CF  device  model:V2545A`。

## 日常注意

- 隧道 URL 会变（quick tunnel 重启就换）。计划任务每 5 分钟同步配置，
  但 **agent 需要再 Reload 一次**才会用新 URL（运行中的进程不重读配置）。
  发现工具调不通 → Reload agent。
- token 泄露 = 别人能只读操作手机（不能写、不能装、不能重启——策略在服务端挡）。
  怀疑泄露就在机械革命重新生成 `shared/tools/adb-mcp/secrets/token.txt`、
  重启 daemon，kaslana 侧重跑一次安装命令，然后 git push 拉齐。
- kaslana 不需要装 adb、不需要 platform-tools、不需要任何 USB。
